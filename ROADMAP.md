# SI JANI roadmap

## Phase 1 — local learning foundation

Implemented: demo onboarding, PostgreSQL persistence, six draft articles, source registry, original concept index, five-format ethics case, draft/resume/retake/history, eleven-dimension self-review, progress dashboard, and protected lecturer inventory. These remain operational.

## Phase 2 — core experience and navigation

Implemented: semantic light/dark themes, responsive shell, collapsible sidebar, accessible mobile navigation, breadcrumbs, profile menu, deterministic JANI guidance, personalized gateway, Blok 1 structure, clearer errors, and in-memory unsaved-work protection. Historical test evidence is retained in PROJECT_STATUS.md.

## Phase 3 — interconnected Encyclopedia and academic content workflow

Implemented: typed knowledge entities with many-to-many domain membership; twelve domain routes; structured theory, concept, and theorist pages; database search; React Flow Knowledge Map with typed relationships and text alternative; evidence-gated comparison; private bookmarks/reading/review/check activity; source metadata and section mappings; protected ingestion/edit/review/publish/revoke workflow; immutable revisions and authorization tests.

The functional demonstration uses three theories, three concepts, six theorist contexts, and 23 relationships alongside the six preserved legacy articles. Five source records remain pending. No real verified comparison, complete reviewed biography, or approved curriculum is claimed. Phase 3's academic publication acceptance remains blocked on source documents and independent authorized human review. Actual validation is recorded in PROJECT_STATUS.md; implementation boundaries and import format are in KNOWLEDGE_ARCHITECTURE.md.

## Phase 4 — case analysis and formative review

Implemented: two synthetic cases with ten questions across the established five formats; versioned narrative/policy snapshots for new simulation attempts; partial written drafts; immutable submitted analyses and parent-linked revisions; versioned eleven-dimension rubric definitions; transparent self-review and scoped instructor review; private review drafts, evidence excerpts, references, final feedback, revision requests, and amendments; four source readers with eight orientation sections; reading and review progress; responsive context/editor workspace.

Case-specific instructor permission is now modeled and enforced. Real staff identity and a trusted grant-administration interface remain outstanding; no privileges are seeded. Source documents, exact section mappings, and rubric/curriculum approval are still unavailable. The numeric results are formative only. AI review remains disabled because no authorized evaluation service exists.

## Phase 5 priority — approved identity, sources, and review governance

Obtain verified user/institutional primary sources and appoint authorized editors/reviewers. Resolve ambiguous editorial inventory names, including “Albert Bigelow Kelly.” Verify source versions and exact sections, review the Behaviorism slice, approve supported relationships, and publish two complete theories so the comparison tool has real approved material. Do not promote seed drafts automatically.

Implement institutional sign-in, account recovery, staff provisioning and reviewer accountability, separate NPM verification, explicit lecturer/student-record grants, and retention/deletion requirements. Existing DOSEN inventory access must not imply editorial or learner-record permissions. No real-account administration occurs without authorization.

## Subsequent development — deeper learning and scale

Extend review administration and history navigation; full knowledge-check attempt history; approved source-document ingestion and bibliographic editing with review; pagination for larger entity collections/source inventories; indexed search and dense graph clustering; source-supported approach/biography expansion; context-aware teaching recommendations only with a specified learning design. Preserve the new immutable case-version and attempt-snapshot rules when adding case authoring. Keep the current scoring/rubric rules unless academically approved changes are requested.

## Production hardening and release

Phase 4 preview preparation: a Vercel Preview build configuration and deployment guide are included. Previews use a separate managed PostgreSQL database, demo-only seed installation, and deployment-specific HTTPS origin checks. This does not implement Phase 5 or approve a production release.

Prerequisites: verified identities, approved curriculum, authenticated managed PostgreSQL, an authorized release target, and operational owners. Validate backups/restores, controlled migrations, concurrency/load, rate limits, privacy-preserving observability, session security, performance, assistive-technology flows, and additional browsers. Release only after acceptance and explicit authorization; a passing local build is not production approval.
